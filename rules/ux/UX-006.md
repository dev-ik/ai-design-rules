# UX-006 Confirm Consequential Actions With Preserved Context

Status: Draft
Domain: UX

## Source Research

- `research/ux/high-risk-operational-flows.md`

## Why

When an action can move money, change account access, publish externally, delete durable data, or let an agent act on the user's behalf, users need to verify the exact consequence without losing the context that made the action meaningful.

## Rule

Before executing a consequential action, show a risk-proportional confirmation or challenge state that preserves the acted-on object, critical inputs, side effects, reversibility, and recovery path.

## Good

- The confirmation keeps the object, amount, recipient, destination, scope, or selected records visible.
- A server-requested challenge adds only the missing confirmation field while preserving entered data.
- The user can still cancel, edit critical inputs, or understand what happens next.
- User-facing copy explains the consequence and recovery path without raw backend codes.
- Agentic actions with real-world side effects require explicit approval and remain interruptible.

## Bad

- A generic modal asks "Are you sure?" while hiding the object and side effects.
- A failed 2FA, KYC, passkey, or agent approval restarts the entire flow unnecessarily.
- The UI shows technical backend codes instead of actionable product language.
- A low-risk reversible action gets the same heavy ceremony as a money movement.
- The agent proceeds with an external side effect because the user gave a broad initial instruction.

## Review

- Identify the actual consequence, reversibility, and affected object.
- Verify that critical context remains visible in confirmation, challenge, error, and retry states.
- Check cancel, edit, retry, and success paths.
- Confirm the recovery state asks only for the missing information.
- For agentic work, verify approval, interruption, and audit evidence before execution.
